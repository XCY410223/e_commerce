## 一、项目概述

### 1.1 项目定位

面向生鲜品类的 B2C 电商平台，采用 Django 全栈（服务端渲染模板）方案，覆盖 **用户、商品、购物车、订单、后台管理** 五大业务域，并配套 Redis 缓存/会话、Celery 异步任务、FastDFS 分布式文件存储四项基础设施。

### 1.2 技术栈基线（已实测）

### 1.3 建设目标

1. `manage.py check` / `migrate` / `runserver` 三件套全部通过，形成**可运行的最小骨架**。
2. 11 张业务表按设计文档落成 Model 并完成首次迁移，`BigAutoField` 主键 + 统一审计字段。
3. 五大模块路由、视图、模板目录就位，前后台可联通。
4. Redis 承载会话、首页缓存、购物车、浏览历史四类数据。
5. Celery 接管邮件发送与页面静态化两类异步任务。
6. 交付一份可复现的依赖清单与启动说明。

### 2.4 一个必须现在决策的时序问题

`django.contrib.auth` 的默认用户表一旦 `migrate` 落库，**再切换到自定义 User 模型将极其痛苦**（需手工改表 + 迁移历史造假）。当前 `db.sqlite3` 为 0 字节、尚未迁移，是设置 `AUTH_USER_MODEL = "user.User"` 的**唯一低成本窗口**。

> **决策：本次搭建第一步就定义 `user.User(AbstractUser)` 并设置 `AUTH_USER_MODEL`，之后才执行首次 `migrate`。**

### 5.2 关键字段定义

**用户表**（复用 auth 体系，`激活标识/权限标识` 由 `is_active`/`is_superuser`/`is_staff` 承载）

```python
# apps/user/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models
from db.base_model import BaseModel

class User(AbstractUser, BaseModel):
    """用户模型：继承 AbstractUser 保留权限体系，叠加统一审计字段"""
    class Meta:
        db_table = "df_user"
        verbose_name = "用户"
        verbose_name_plural = verbose_name

class Address(BaseModel):
    user = models.ForeignKey(User, on_delete=models.CASCADE, verbose_name="所属用户", related_name="addresses")
    receiver = models.CharField(max_length=20, verbose_name="收件人")
    addr = models.CharField(max_length=256, verbose_name="详细地址")
    zip_code = models.CharField(max_length=6, verbose_name="邮编")
    phone = models.CharField(max_length=11, verbose_name="联系电话")
    is_default = models.BooleanField(default=False, verbose_name="默认地址")

    class Meta:
        db_table = "df_address"
        verbose_name = "收货地址"
```

# apps/goods/models.py
class GoodsType(BaseModel):

    type = models.ForeignKey(GoodsType, on_delete=models.CASCADE, verbose_name="商品种类")
    spu = models.ForeignKey(GoodsSPU, on_delete=models.CASCADE, verbose_name="商品SPU")
    name = models.CharField(max_length=100, verbose_name="商品名称")
    spec = models.CharField(max_length=20, blank=True, default="", verbose_name="规格")
    desc = models.CharField(max_length=256, verbose_name="商品简介")
    price = models.DecimalField(max_digits=10, decimal_places=2, verbose_name="单价")

    stock = models.IntegerField(default=0, verbose_name="库存")
    sales = models.IntegerField(default=0, verbose_name="销量")        # 冗余，避免实时 sum
    status = models.SmallIntegerField(choices=STATUS_CHOICES, default=1, verbose_name="状态")

    class Meta:
        db_table = "df_goods_sku"
        indexes = [
            models.Index(fields=["type", "status"], name="idx_sku_type_status"),
            models.Index(fields=["spu"], name="idx_sku_spu"),

class GoodsImage(BaseModel):
    sku = models.ForeignKey(GoodsSKU, on_delete=models.CASCADE, related_name="images")

### 5.3 索引与冗余策略

| 策略 | 落点 | 理由 |
| --- | --- | --- |
| 冗余销量 | `GoodsSKU.sales` | 列表页排序/展示，避免每次 `COUNT` 订单明细 |
| 冗余总价 | `OrderInfo.total_count / total_amount` | 订单列表与支付只需读单表 |
| 价格快照 | `OrderGoods.price` | 商品调价不影响历史订单 |
| 覆盖索引 | `(type, status)` | 分类列表页 `WHERE type=? AND status=1` |
| 联合索引 | `(user, -create_time)` | 用户订单列表分页 |
| 唯一约束 | `OrderInfo.order_id` | 幂等下单、防重复支付 |

> 设计文档标注的"以空间换时间"即上述**冗余字段 + 覆盖索引**两组手段，属有意为之，不做范式化。

### 5.4 Redis 键设计

| 用途 | Key | 类型 | 说明 |
| --- | --- | --- | --- |
| 会话 | `session:<session_key>` | String | `SESSION_ENGINE = django.contrib.sessions.backends.cache` |
| 首页缓存 | `index_content` | String | 序列化后的上下文，TTL 3600s |
| 商品详情 | `goods_detail:<sku_id>` | String | TTL 3600s |
| 购物车（登录） | `cart:<user_id>` | Hash | field=`sku_id`，value=`count` |
| 购物车（游客） | Cookie `cart` | JSON | `{sku_id: count}`，登录后合并入 Redis |
| 浏览历史 | `history:<user_id>` | List | `LPUSH` + `LTRIM 0 4`，保留最近 5 条 |

### 6.4 文件存储：FastDFS 抽象层

`fdfs_client-py` 长期未维护，在 Python 3.13 上**不可用**。方案是自建 Storage 后端，走 FastDFS 的 HTTP 上传接口，并把"本地存储"作为降级实现：

```
utils/storage.py
  ├── class FastDFSStorage(Storage)   # 生产：POST 到 tracker/nginx
  └── class LocalMediaStorage(Storage)# 开发：落到 MEDIA_ROOT
```

```python
# settings.py
DEFAULT_FILE_STORAGE 已废弃，改用：
STORAGES = {
    "default": {"BACKEND": os.getenv("STORAGE_BACKEND", "utils.storage.LocalMediaStorage")},
    "staticfiles": {"BACKEND": "django.contrib.staticfiles.storage.StaticFilesStorage"},
}
```

> 开发期不阻塞：`STORAGE_BACKEND` 默认走本地，等商品图入库阶段再切 FastDFS，避免因分布式存储未就绪卡住整条链路。

### 6.6 用户模型时序（最高优先级）

```
① 写 apps/user/models.py: class User(AbstractUser, BaseModel)
② settings.py: AUTH_USER_MODEL = "user.User"
③ 删除 db.sqlite3（0 字节残留）
④ 首次 makemigrations user → migrate
```

**顺序不可颠倒**。若先 `migrate` 建了 `auth_user`，再切自定义模型，将触发 `InconsistentMigrationHistory`，只能清库重来。

### B. 修复后的 `config/urls.py`（对照版）

```python
from django.contrib import admin
from django.urls import path, include, re_path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("tinymce/", include("tinymce.urls")),
    path("user/", include("user.urls", namespace="user")),
    path("cart/", include("cart.urls", namespace="cart")),
    path("order/", include("order.urls", namespace="order")),
    path("", include("goods.urls", namespace="goods")),   # 兜底路由必须最后
]
```

> 对照原文件：`url()` → `path()`（Django 5.0 起 `url` 已移除）；补 `include` 导入；`tinmce` → `tinymce`；空字符串路由 `r"^"` 会导致后续规则永不匹配，故置于末位。

### C. 各 `urls.py` 应补的 `app_name`

```python
# apps/user/urls.py
app_name = "user"          # 否则 include(..., namespace="user") 抛 ImproperlyConfigured
urlpatterns = []
```

`goods` / `cart` / `order` 同理，且**必须删掉 `apps/user/urls.py` 中从根路由复制来的全部 `include` 语句**。
